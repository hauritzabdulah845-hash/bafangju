执行说明

1. 先在服务器部署并执行 npm test，全绿后再开始页面验收。

2. 每行右侧点「通过 / 不通过 / 阻塞」记录结论，结果自动保存在本机浏览器，刷新不丢；换电脑需重新记录。

3. 点顶栏搜索框可按编号、步骤、预期结果过滤；也可只看「待测」或「不通过」。

4. 点「打印 / 导出 PDF」用 A4 横向出纸质单，结论列会变成手写横线。

5. 不通过必须附截图 + Console 报错 + 复现步骤，便于开发定位。

一、测试环境与准备

后台地址：https://<服务器域名>/admin.html　｜　浏览器：Chrome / Edge 最新版 + 1 台 1366×768 笔记本

账号 A：总账号 super（全部权限）　｜　账号 B：子管理员，仅勾选「商品管理 + 订单管理」

小程序：用户端、商家端体验版各 1 个，用于首页运营帧与「赚实惠」页回归

部署与自动测试：cd bafangju-server && npm test && pm2 restart bafangju，预期全绿（含 test/ops-content.test.js 违规词回归）

数据准备：待审商品 ≥1、待审入驻 ≥1、待审提现 ≥1、广告计划草稿与投放中各 1、含「返利」的运营帧文案 1 条、可清空的空数据环境

通过标准
  1. P0 用例 100% 通过；P1 通过率 ≥ 95%；无「致命 / 严重」缺陷。
  2. npm test 全绿（含违规词回归用例）。
  3. 违规词前后端双层拦截均验证通过（TC-P0-08 ~ TC-P0-11）。
  4. 16 个菜单均可正常进入，无空白页、Console 无红色报错。

不在本次范围：后端资金记账/分账算法正确性、微信真实打款联调、小程序端 UI 视觉改版、性能压测。
