# 微信支付联调清单（真实商户号 + 真实回调域名）

> 前提：`npm test` 与 `npm run drill` 全绿后再做。本文只列"要准备什么、按什么顺序切、怎么验、还缺什么"。

## 一、需要准备的材料

| 材料 | 用途 | 对应环境变量 |
| --- | --- | --- |
| 商户号（mchid） | v3 下单主体 | `WX_MCHID` |
| 小程序 AppID（与商户号已关联） | JSAPI 下单 / 支付签名 | `WX_APPID` |
| 商户 API 证书序列号 | 请求签名头 `serial_no` | `WX_MERCHANT_SERIAL` |
| 商户 API 私钥（`apiclient_key.pem`） | v3 请求签名 + 小程序 `paySign` | `WX_PRIVATE_KEY`（PEM 全文） |
| APIv3 密钥（32 字节） | 回调 resource 解密 | `WX_APIV3_KEY` |
| 微信支付平台证书（PEM） | 回调验签 | `WX_PLATFORM_CERT` |
| 回调地址 | 支付结果通知 | `WX_NOTIFY_URL`（或代码里默认值） |
| 小程序 AppSecret | `code2session` | `WX_SECRET` |

另外两件**平台配置**，不是代码：

1. 小程序后台 → 开发设置 → 服务器域名 → 把后端域名加入 **request 合法域名**（`wx.requestPayment` 还需要商户号与 AppID 完成关联）。
2. 回调域名必须 **HTTPS + 已备案**，且能被微信公网访问（`https://你的域名/api/payment/notify-wx`）。

## 二、切换顺序（建议）

```bash
# 1) 先确认当前是 mock
curl https://你的域名/api/payment/config
# => {"mode":"mock","provider":"mock","mock":true}

# 2) 配好上面 6 个环境变量（WX_MCHID/WX_APPID/WX_MERCHANT_SERIAL/WX_PRIVATE_KEY/WX_APIV3_KEY/WX_PLATFORM_CERT）
#    可选：PAY_MODE=live 强制真实（缺配置会直接报错，不会静默降级）

# 3) 重启后再次确认
curl https://你的域名/api/payment/config
# => {"mode":"live","provider":"wxpay","mock":false}
```

`PAY_MODE` 的三种用法：

- 不设置：配齐 4 个必需变量 → 自动 live；没配 → 自动 mock；
- `PAY_MODE=mock`：强制模拟（**财务演示/内部培训专用**，避免误扣真钱）；
- `PAY_MODE=live`：强制真实，缺配置直接 400，防止"以为在收钱其实没接"。

## 三、联调用例（建议按顺序）

| # | 用例 | 预期 |
| --- | --- | --- |
| 1 | 正常下单 → 支付 | 小程序弹出微信收银台，支付成功后订单 3 秒内变"已支付"，进度 +1 |
| 2 | 支付后不点确认，等回调 | `GET /api/orders/:id` 轮询到 paid（不依赖前端回调） |
| 3 | 取消支付 | 提示"已取消支付"，订单仍为待支付，可再次发起 |
| 4 | 超 90 分钟后再支付 | 服务端自动重新预下单（prepay_id 约 2 小时过期） |
| 5 | 重复点击支付 | 同订单返回同一预支付参数（`replay: true`），不会重复扣款 |
| 6 | 伪造回调（不带签名） | `notify-wx` 返回 400，不入账，审计记 `payment.notify_wx_rejected` |
| 7 | 篡改回调 body | 验签失败 400，不入账 |
| 8 | 同一笔回调重放 | `onPaid` 幂等，订单只入账一次 |
| 9 | 金额一致性 | 回调 `amount.total` 与订单 `paidFen` 不一致时应告警（当前只做入账，建议加断言） |
| 10 | 退款 | **见下方已知缺口** |

## 四、已知缺口（联调前需要决定）

1. **退款未调用微信退款 API**：`svc.refundOrder` 只把订单改成本地 `refunded` 并回滚分佣，**不会真的退钱**。真实上线前必须接 v3 `POST /v3/refund/domestic/refunds`，并把退款单号/状态落库。
2. **只支持全额退款**：无部分退款、无多次退款。
3. **未接对账单下载**：`/v3/bill/tradebill` 未接，月度对账目前只能人工比对（本地口径可用 `npm run drill` 校验）。
4. **支付结果页**（P1）：目前是 toast + 轮询，没有独立结果页与"重新支付/查看订单"入口。
5. **回调金额校验**：建议在 `notify-wx` 里加一条 `paidFen === order.paidFen` 校验，不一致拒绝入账并告警。

## 五、对账建议（上线首月）

- 每天导一次微信交易账单，与本地 `orders`（`payType=WX_PAY` 且 `status != refunded/cancelled`）按 `out_trade_no` 对；
- 差异只可能来自三类：回调丢失（补单）、退款未回传（缺口 1）、金额不一致（缺口 5）；
- 月末跑一次 `npm run drill` 确认本地四本账自洽，再与微信账单做外部核对。
