**影响**：未登录用户可无限次上传 ≤4MB 的 png/jpg/webp 文件到 `data/uploads/`，用于**占满磁盘**（DoS）或**存放违规内容**（上传的文件通过 `/uploads/xxx` 静态目录公开可访问）。文件名的随机性来自 `Date.now()` + `Math.random()`，可预测性低但不足以替代鉴权。

**修复方案（与原报告方案的偏差已说明）**：
1. ~~挂 `requireUser` 中间件~~ → **原方案有冲突，改为「统一入口 + 身份分级」**：报告原定挂 `requireUser`，但该接口的唯一调用方是**商家端小程序**，其鉴权用的是**商家令牌**（`merchants.token`）而非用户会话（`userSessions`）；且入驻申请链路本就允许未登录上传营业执照，直接挂 `requireUser` 会**打断这条链路**。最终按用途分流：

2. 增加单主体 / 单 IP 频率限制与每日总量配额（分钟级频控 + 每日次数与容量三重计数）。
3. 文件名改用 `crypto.randomUUID()`。
4. 校验文件真实 MIME（读文件头 magic bytes），不信任 `ext` 参数。
5. **证照私有化**：`data/uploads-private` 不挂静态路由，只能经 `/api/admin/uploads/private/:name` 由管理后台鉴权后获取。
